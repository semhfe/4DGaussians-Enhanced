# 4DGS Enhanced Notebook v1.1 Release Notes

## Overview
This release introduces significant architectural enhancements to the 4DGaussians-Enhanced notebook, focusing on rig calibration, enhanced extraview processing with integrity checks, and comprehensive pipeline validation.

## 🆕 New Features

### 1. Cell 3.2: Rig Calibration Workflow
A complete rig calibration system for multi-camera setups:

**Hybrid Input Detection**
- Automatically detects input type (image folders or video files)
- Priority 1: Scans for image subfolders (cam01/, cam02/, ...)
- Priority 2: Detects video files and extracts frames using ffmpeg
- Creates clean workspace with standardized structure

**COLMAP Rig Pipeline**
- Feature extraction with per-folder camera assignment
- Sequential matching for temporal coherence
- Rig bundle adjustment for relative pose estimation
- Mapper with rig constraints (ba_refine_sensor_from_rig=0)

**Sanity Checks**
- Validates exactly 8 cameras are registered
- Warns about reprojection errors > 1.5 pixels
- Provides clear error messages and instructions

**Data Swap Logic**
- Saves calibration as `sparse_calibrated`
- Provides instructions to swap calibration images with subject images
- Preserves rig calibration parameters across datasets

### 2. Cell 3.5: Enhanced Extraview Strategy
Major improvements to the extraview processing pipeline:

**Pose Drift Detection**
- Backs up all main camera poses BEFORE filtering
- Re-validates poses AFTER filtering extra views
- Compares with tolerance of 1e-6 for all pose parameters (QW, QX, QY, QZ, TX, TY, TZ)
- Raises critical error if any main camera pose has drifted
- Ensures pose integrity is never compromised

**Filtering Logic**
- Filters based on `"extra" not in filename.lower()`
- Does NOT assume sequential naming (image00, image01, etc.)
- Preserves all main camera data
- Reports filtering statistics

**Full Logging**
- Removed ALL `> /dev/null` redirects
- Removed ALL `2> /dev/null` error suppression
- Full visibility of COLMAP operations
- No `-q` flags on CondaColab installation

### 3. Cell 4.5: Mask Verification Sanity Check
Automated mask quality validation:

**Empty Mask Detection**
- Scans all mask files in the mask directory
- Computes non-zero pixel counts
- Detects empty/all-black masks
- Reports coverage percentage for valid masks

**Pre-Training Validation**
- Raises error if no mask files found
- Warns if masks are empty
- Samples first 10 masks for quick validation
- Prevents training with invalid masks

### 4. Cell 6.5: Training Pre-check
Comprehensive pre-training validation:

**Path Verification**
- Checks source_path exists and is populated
- Validates model_path output directory
- Confirms sparse model directory (sparse/0)
- Verifies images directory
- Checks mask_path if masks are enabled

**Sparse Model Validation**
- Verifies presence of cameras.bin, images.bin, points3D.bin
- Reports file sizes for sanity checking
- Detects missing or corrupted model files

**Configuration Summary**
- Displays all training parameters before start
- Shows mask count if masks enabled
- Provides clear go/no-go decision
